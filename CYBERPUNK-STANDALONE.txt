Cyberpunk VR standalone compatibility
====================================

Cyberpunk VR Port 0.1.8 asymmetric cameras (2026-10-20)
------------------------------------------------------
The port still renders MAIN and VRCAM, but now normally uses asymmetric
per-eye projections. Shared gaze must not borrow one asymmetric camera for
both eyes. The lower D3D12 path now carries the exact Streamline frame and
viewport camera through its nested NGX evaluation and binds it to that
evaluation's native handle. No assumptions about eye evaluation order.
The old symmetric-only, 100ms fallback remains for older port versions.

Keep CenterMode=3 and the port's asymmetric projection enabled. This change
requires only the rebuilt standalone runtime DLL; it does not require a new
port DLL, global OpenXR layer, host DLL, proxy, registry or UEVR deployment.
Missing/wrong-frame/expired camera data remains rejected; no raw headset-UV
fallback was introduced. UEVR's host projection publication is unchanged.

First headset test of the call-scope patch failed: real Streamline viewport
inputs were not recognized because the local ABI wrapper's type GUID was zero.
Corrected ViewportHandle initialization to the official GUID/version, and
retained multiple in-flight frame cameras rather than overwriting each viewport
with only its newest frame. The production-header GUID test fails on the old
wrapper and passes on the correction. Do not describe the first build as working.

Expanded --cyberpunk-shared-gaze regression passes asymmetric optical centers,
reversed/repeated view order, non-square output, frame/viewport/age rejection,
nested scope restoration and thread isolation. Headset confirmation pending.
After loading gameplay, verify BOTH foveated regions follow eye movement;
support logs should show fresh=1, reject=0 and the appropriate cameraVP for
each native view. This does not fix or validate the port's native framegen.

Optional shared gaze for the standalone triple-DLSS5 branch
----------------------------------------------------------
This branch restores the optional shared-gaze compatibility mode removed by
upstream commit 0d22b6a, while retaining manual mapping and independent-input
options. It does not change DLSS-NR multipass processing or global defaults.

In CheekyFoveatedDLSS.ini, [CheekyFoveatedDLSS], set CenterMode=3 (or select
"Shared right-eye gaze (Cyberpunk compatibility)" in Stereo / Gaze).
One valid right-eye gaze ray drives BOTH render views after conversion into
the game's render-camera projection. This is not calibrated stereo mapping;
eye-order inversion is not used. Check the per-view tracking count, not merely
whether a gaze signal exists. Missing/stale projections or unfocused/invalid
gaze cause fallback rather than guessed headset-UV placement.

For native NGX calls without a projection scope, recent symmetric camera
reuse is restricted to CyberpunkVR_Stereo.dll and expires after 100ms.
Publication and display-time freshness, session changes and per-publisher
camera invalidation remain enforced. Existing CenterMode=3 profiles retain
their intended behavior instead of being normalized to fixed mode.

Optional CheekyRuntime.ini beside the runtime DLL:
  [Calibration]
  Enabled=0
This disables marker acquisition at startup without disabling gaze. The newer
manual-mapping calibration gate is preserved. Other installations keep their
default behavior. Retain the F11 override below to avoid the port's F8 binding.

Regression checks on this branch passed for shared gaze on both native views,
projection/freshness/session/cache safety, mode serialization and reconnect,
calibration startup opt-out, controller bindings, overlay input/rendering and
standalone bootstrap. Added checks:
  CheekyTests.exe --cyberpunk-shared-gaze
  CheekyRuntimeHostTests.exe --calibration-disabled
Both are registered in CTest and scripts/build.ps1. This restored implementation
has prior Cyberpunk headset history; this particular triple-DLSS5 combination
still needs headset and actual NVIDIA multipass inference validation.

Scope and validation
--------------------
Developed against upstream v0.5.4 (d6c18b2). The standalone host/runtime and
OpenXR layer were tested with Cyberpunk VR Port 0.1.7, PSVR2 eye tracking,
SteamVR/OpenXR and external OFXR. The tester confirmed working menu controls
on 2026-09-30.
This is not a claim of testing every runtime, headset, frame-generation mode
or game. No Cyberpunk port code change is part of this patch.

Problems addressed
------------------
1. Preserve host controller bindings when menu graphics becomes available.
   Applications can suggest bindings before creating their graphics session.
   Deferred menu setup must augment the successful host suggestion, not replace
   it. Failed suggestions do not replace the cache; unknown extension chains
   are not retained by pointer or replayed without their semantics.
2. Avoid an unconfirmed optional cylinder request for CyberpunkVRPort when the
   downstream extension enumeration is unavailable. Keep application requests
   intact and use the quad fallback. A failed speculative create/retry was
   associated with missing controls/black-world startup failures in testing;
   this is not asserted to explain every possible startup failure.
3. Use a single owner for headset menu presentation. Once OpenXR is actively
   consuming the menu, do not also publish the texture through OpenVR. The
   no-cylinder fallback uses one full-image sampled quad; busy DX12 allocators
   are treated as temporary backpressure. The final menu stopped crashing in
   testing; the original driver crash alone did not prove a unique cause.
4. Preserve actual clicks. Apply raw mouse motion before button edges so game
   cursor warping cannot redirect the click. Queue XR press/release edges across
   independent render cadences and arbitrate desktop/controller ownership.
   When custom SteamVR bindings omit the layer's menu actions, use the host's
   already-bound aim/trigger as a read-only fallback. Do not replace user
   bindings, create a second runtime session or resynchronize game action sets.

Setup (explicit opt-in; global defaults are not changed)
--------------------------------------------------------
Use matching standalone host/runtime and OpenXR layer builds. In the game's
CheekyFoveatedDLSS folder beside the standalone runtime DLL:

  CheekyOverlay.ini:
    [Overlay]
    MenuKey=122
    TextScalePercent=175

122 is F11. Avoid F8 with Cyberpunk VR Port: it controls the port's flat window.
TextScalePercent is clamped to 100..250; the menu scales and recenters on open.

Overlay tests verify actual checkbox changes, not only cursor movement.
These tests do not replace headset validation.

Additional production OpenXR interception tests (D3D11 and D3D12):
  cmake -S tests/openxr_binding -B build/openxr-binding-tests -A x64
  cmake --build build/openxr-binding-tests --config Release
  ctest --test-dir build/openxr-binding-tests -C Release --output-on-failure

Cover early/late suggestions, failed/replaced suggestions, unknown chains,
host action-set preservation, unchanged downstream input results, optional
extension startup, menu ownership, pointer edges, host-action fallback for both
hands, ray loss and profile/session cleanup. No game install is required.
